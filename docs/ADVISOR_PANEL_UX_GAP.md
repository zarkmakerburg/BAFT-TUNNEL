# Advisor note: panel UX gaps from screenshots

Status: advisory, 2026-11-17. Extends §6 of [ADVISOR_ASSESSMENT.md](ADVISOR_ASSESSMENT.md). Not a decision record.

**Evidence and its limit.** Screenshots in the project file store (`screenshots/panel-polish/desktop-en-light-overview.png`, `tablet-fa-dark-tunnels.png` (a narrow, phone-width layout), `screenshots/p4-002/desktop-en-wiz-preflight.png`). They show a local agent with one demo tunnel in an unpaired state, and the sidebar reads `v0.1.0`. They are **not** captures of current `main` and not of a healthy paired pair, so findings about empty or Unknown states may disappear once a tunnel is running. Re-capture on the current build before acting; this note proposes no UI change by itself.

| # | Observation (what the screenshot shows) | Why it matters | Suggested check or change | Priority |
|---|---|---|---|---|
| U-1 | Overview keeps Unknown honest: no fake numbers, "never says ready", dashed Unknown badges, empty states say why ("agent started without --instance") | This is the product's strongest UX trait; no reference project README claims it | Keep as an acceptance rule; add a test that every metric card has a source and freshness line | keep |
| U-2 | "Local connect latency" and "Tunnel health (local probe)" measure the local listener, not the peer path | An operator may read 18 ms as tunnel latency. RTT/jitter/loss across the tunnel are absent (assessment R-1) | Rename the card to make "local listener" explicit, and add the peer-path RTT card only after R-1 is wired | P1 |
| U-3 | Three overlapping cues: header Unknown pill, top banner Unknown, "Configured tunnels" card repeating the same sentence "State is built from unit evidence...", plus a count "Needs action: 3" | Noise; a new user must read the same sentence twice and still not know the first action | One status banner; put the single most useful next step in it (for example "start the service on this host") | P2 |
| U-4 | Availability card shows "0%" with "last 9 samples" beside a 24 h figure of 83.9% in the warnings | A 0% from nine samples reads as an outage and conflicts with the 24 h number | Show sample count and window together, and gray out a figure below a minimum sample count | P2 |
| U-5 | Create-tunnel wizard, step 4: certificate files missing is "Blocked", "Resolve the blocked items to continue", with no in-wizard action; wizard says nothing is applied on any host | The Install, Connect, Create flow stalls at the first real step for a non-expert; the user must leave the wizard to find a CLI or pairing path | Each Blocked row gets one linked remedy (open pairing, run the guided command) and says which page does it | P1 |
| U-6 | Config directory and port 8080 in use are Warning, not Blocked, and the check list has nine rows with equal weight | Hard to see which row stops progress | Sort Blocked first and collapse Pass rows | P3 |
| U-7 | Peer reachability, Peer identity, Firewall are Unknown by design (read-only, ADR-0030) | Correct, but Peer reachability could be measured by a read-only dial; Unknown for a thing that is cheap to check is a missed value | Evaluate a read-only peer dial in preflight (ties to doctor, assessment R-8); Firewall stays Unknown | P2 |
| U-8 | Phone-width Persian tunnels page: one long column of mostly Unknown fields; the label "آخرین تأیید" value runs two words together ("انتهابه‌انتها"); the percent sign appears on the wrong side of the digits ("% ۰") | Bidi and spacing defects in fa; long Unknown list hides the single action ("diagnose this tunnel") | Group Unknown fields under a collapsed "Not yet measured" row; add RTL bidi isolation around numeric values; ask a Persian reader to review the wording | P2 |
| U-9 | No join link or pairing shortcut visible from Overview or the wizard | Compared with other tools' one-line join pattern (assessment §6) | See assessment R-7 | P2 |

Not covered: dark/light contrast and keyboard accessibility (an automated axe audit already runs in CI per the roadmap), and any screen not in the three screenshots.
